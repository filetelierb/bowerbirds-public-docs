## Sign in

```sh
bowerbirds cloud login
bowerbirds cloud whoami
```

Login asks for an email and sends a sign-in link. The session is shared with cloud commands on that device.

Use `bowerbirds cloud logout` to remove it.

## Work as an agent

A coding agent should not act as you. Log the CLI in as an agent through OAuth: the browser signs you in, you pick the workspace and the role, and the CLI receives a short-lived access token and a rotating refresh token.

```sh
bowerbirds cloud tokens login [--role read|contribute|admin|router] [--no-browser]   # --scope is an alias
bowerbirds cloud tokens status
bowerbirds cloud tokens logout
```

The credential lives in `~/.bowerbirds/agent-token.json` (mode 600) and refreshes itself. `--token bbt_…` or `BOWERBIRDS_TOKEN` present a token minted by hand instead, and take precedence. Every cloud verb then acts as the token.

```sh
bowerbirds cloud records list me/qa/login --kind capture,note --unsigned --limit 50 --json
bowerbirds cloud records list me/qa --since 2026-09-01T00:00:00Z --cursor <cursor>
bowerbirds cloud records show me/qa <item-id> --json
bowerbirds cloud records context me/qa <item-id> [--part summary|findings|chunks] [--refresh]
bowerbirds cloud records push-capture me/qa/login --image annotated.png --original raw.png \
  --session session.json --title "Login form" --content "Global comments:\n 1. Button off-center"
bowerbirds cloud records move me/qa --ids <id,id> --to me/archive/done
bowerbirds cloud records trash me/qa --ids <id,id>
bowerbirds cloud records sign me/qa --ids <id,id>
bowerbirds cloud records unsign me/qa --ids <id,id>
```

Locations are `owner/slug[/directory/path]`; `me` is the token's workspace. `--signed` and `--unsigned` filter on the token's own mark, and `--json` answers `signed` on every row. `records context` reads the findings the [media processor](/cloud/media) condensed a recording, audio file, PDF or set of pictures into; `--refresh` recomputes it and spends the workspace's credits. See [Agent tokens](/mcp/agent-tokens) for minting, listing and revoking:

```sh
bowerbirds cloud tokens mint --label "ci reviewer" --role contribute [--bucket me/qa]
bowerbirds cloud tokens list [--bucket me/qa]
bowerbirds cloud tokens revoke <id> [--bucket me/qa]
```

## Workspaces

```sh
bowerbirds cloud workspaces list
bowerbirds cloud workspaces create "Acme Research"
bowerbirds cloud workspaces use acme-research
bowerbirds cloud workspaces members acme-research
```

Add `--workspace <id-or-slug>` to a cloud command to target a workspace without changing the device's active workspace. A workspace id is spelled `ws_…` — `ws_p_…` for a personal workspace — and that same id is what RevenueCat identifies the subscriber by.

## Push, pull, and sync

```sh
bowerbirds cloud push launch-research
bowerbirds cloud pull me/launch-research --as launch-research-copy
bowerbirds cloud sync launch-research on
```

- `push` sends a local Bucket to a cloud owner/slug.
- `pull` materializes a cloud Bucket locally under a chosen name.
- `sync on` enables continued synchronization for the local Bucket.

## Read cloud records

```sh
bowerbirds cloud records list <local-location-slug> --json
bowerbirds cloud records list <owner/slug[/path]> [--exact] [--kind a,b] [--since RFC3339] [--limit N] [--cursor c] --json
bowerbirds cloud records search "address validation" \
  --bucket <bucket-cloud-slug> \
  --kind capture \
  --limit 20 \
  --json
bowerbirds cloud records show <bucket-cloud-slug> <item-id> --json
```

For capture-focused exports, use `cloud captures <owner>/<slug>` to sweep manifests and `cloud capture <owner>/<slug>/<item-id>` to write one manifest and its payloads to disk.

## Process a recording

```sh
bowerbirds cloud recording process research <item-id> \
  --template walkthroughGuide \
  --frames 4.2,17.0,38.5 \
  --follow
```

With `--json`, follow mode emits newline-delimited progress events. See [Recording processing](/workflows/video-processing) for the output model.

Payload downloads use a cache directory and an optional version stamp:

```sh
bowerbirds cloud records payload <bucket-cloud-slug> <item-id> annotated.png \
  --cache-dir ./cache
```

## Share with people

```sh
bowerbirds cloud share launch-research teammate@example.com \
  --role contribute
bowerbirds cloud share launch-research --members
bowerbirds cloud share launch-research --revoke <uid>
```

Human Bucket roles are `read`, `contribute`, and `admin`. Agent tokens add a fourth, `router`, that only adds and signs; see [Agent tokens](/mcp/agent-tokens).

## Routers

A router sits on one Bucket and dispatches what lands there; see [Routers](/cloud/routers) for kinds, routes, the gate and signatures. The CLI files a router from a JSON document and runs, reviews and answers for it.

```sh
bowerbirds cloud routers list
bowerbirds cloud routers show <router-id>
bowerbirds cloud routers create --file router.json
bowerbirds cloud routers create --kind external --token <token-id> --name <name> --bucket <owner/slug>
bowerbirds cloud routers update <router-id> --file router.json
bowerbirds cloud routers delete <router-id>
bowerbirds cloud routers run <router-id> [--items id,id] [--follow]
bowerbirds cloud routers runs <router-id> [--cost]
bowerbirds cloud routers attention [<router-id>] [--state open|handled]
bowerbirds cloud routers answer <attention-id> --alternative <n> | --text "<answer>"
bowerbirds cloud routers apply <run-item-id> [--strike op-1,op-2]
```

- `create` refuses a second router on a Bucket, naming the one it already has.
- `run` starts one cycle now; `--items` limits it to named records, `--follow` streams progress and exits with the parked reason when the cycle pauses for credits or storage.
- `runs --cost` lists each cycle with what it cost.
- `attention` lists the questions the gate raised — an untrusted external create, a clamp, a tripped breaker, a budget shortfall, a refused connector, or a route's explicit ask — and `answer` picks one of the row's alternatives by number or gives your own words. Answering runs a child cycle over the flagged records only.
- `apply` writes a reviewed plan for one run item; `--strike` drops the named operations before it is applied.

An external router — your own agent as the Bucket's brain — is created the same way with `"kind": "external"`; see [External routers](/cloud/external-routers).

## Connectors, plugins and skills

What a router can reach. A **connector** is the workspace's one connection to an MCP server; a **plugin** installs skills, route templates and connector declarations from a public GitHub repository; a **skill** is a workspace document a route snapshots into its run. See [Plugins](/integrations/plugins).

```sh
bowerbirds cloud mcp-servers list
bowerbirds cloud mcp-servers show <connector-id>
bowerbirds cloud mcp-servers add https://mcp.linear.app/mcp [--name linear]
bowerbirds cloud mcp-servers add https://example.com/mcp --token <bearer-token>
bowerbirds cloud mcp-servers health [--check]
bowerbirds cloud mcp-servers check <connector-id>
bowerbirds cloud mcp-servers remove <connector-id>

bowerbirds cloud plugins install filetelierb/bowerbirds-plugins [--ref main]
bowerbirds cloud plugins list
bowerbirds cloud plugins show <plugin-id>
bowerbirds cloud plugins templates
bowerbirds cloud plugins upgrade <plugin-id>
bowerbirds cloud plugins remove <plugin-id>

bowerbirds cloud skills list
bowerbirds cloud skills show <skill-id>
bowerbirds cloud skills create <name> --file body.md [--description "<text>"]
bowerbirds cloud skills update <skill-id> [--file body.md] [--description "<text>"]
bowerbirds cloud skills delete <skill-id>
```

`mcp-servers add` with a URL alone registers the connector as `needs-connecting` and answers how to finish: a browser link when the server offers OAuth, or the `--token` form when it does not. Plugin verbs are for a workspace owner or administrator.

## Answer an RFI

```sh
bowerbirds cloud rfis list --state open
bowerbirds cloud rfis answer <rfi-id> "Use the production workspace"
```

Processing resumes after the answer is filed. A router's questions live in its attention queue (`cloud routers attention`) and are answered there.
