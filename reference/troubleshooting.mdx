---
title: "Troubleshooting"
description: "Resolve common CLI, MCP, authentication, and sync problems."
icon: "wrench"
---

<AccordionGroup>
  <Accordion title="My MCP client shows no tools or never opens the approval page">
    Make sure the client is configured for the remote HTTP door, not the retired local server. Restart the client after saving its configuration; the first tool call opens the approval page.
  </Accordion>
  <Accordion title="The approval page says I cannot authorize an agent">
    Only an owner or an administrator of a workspace can approve one. Sign in with the account that administers the workspace, or ask its owner.
  </Accordion>
  <Accordion title="The agent stopped working after a while">
    Its grant was revoked, or its refresh token was used twice. Connect again; the client repeats the approval.
  </Accordion>
  <Accordion title="A record exists in the app but not in CLI or MCP">
    It may still be in private Unsorted. File it into a Bucket or directory first.
  </Accordion>
  <Accordion title="The agent needs a payload's bytes">
    Payload bytes never come through MCP. Every payload answers a short-lived URL; fetch it with a plain HTTP GET within 15 minutes.
  </Accordion>
  <Accordion title="A Scratchpad update conflicts">
    Another writer changed it first. Call `get_scratchpad` again, reconcile with the latest content, and retry with the returned revision.
  </Accordion>
  <Accordion title="A remote connection cannot read or write">
    Confirm in Settings → Developer Tools that the connection is still active and has the required role. A `read` grant cannot file, move or trash.
  </Accordion>
  <Accordion title="A payload URL is refused">
    It expired (15 minutes), was tampered with, or its token was revoked. Fetch the record again for a fresh URL.
  </Accordion>
  <Accordion title="I trashed a local record but still see a cloud copy">
    Local and cloud removal are separate actions. Remove the cloud record explicitly if it should no longer be shared.
  </Accordion>
  <Accordion title="A command did not return one JSON document">
    Check `bowerbirds <command> --help` for JSON support. Commands that follow ongoing work may emit newline-delimited JSON events.
  </Accordion>
</AccordionGroup>
