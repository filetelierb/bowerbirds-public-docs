---
title: "Troubleshooting"
description: "Resolve common CLI, MCP, authentication, and sync problems."
icon: "wrench"
---

<AccordionGroup>
  <Accordion title="My local MCP client shows no tools or calls fail authentication">
    Run `bowerbirds cloud login` using the same executable configured in the MCP client, then restart the client.
  </Accordion>
  <Accordion title="The MCP tools look older than the app">
    Call `get_server_info` and check the reported Bowerbirds version. Point the client to `/Applications/Bowerbirds.app/Contents/Helpers/bowerbirds`, then restart it.
  </Accordion>
  <Accordion title="A record exists in the app but not in CLI or MCP">
    It may still be in private Unsorted. File it into a Bucket or directory first.
  </Accordion>
  <Accordion title="A payload is too large for the MCP response">
    Use `bowerbirds item fetch`, `bowerbirds capture export`, or `import_local_file` so the file moves through the filesystem instead of the model context.
  </Accordion>
  <Accordion title="A Scratchpad update conflicts">
    Another writer changed it first. Call `get_scratchpad` again, reconcile with the latest content, and retry with the returned revision.
  </Accordion>
  <Accordion title="A remote connection cannot read or write">
    Confirm that the credential is still active and has the required role on the intended Bucket. Ask the workspace administrator to replace it if necessary.
  </Accordion>
  <Accordion title="A remote file download is refused">
    Make sure the client sends the same authorization credential when fetching the authenticated download URL.
  </Accordion>
  <Accordion title="I trashed a local record but still see a cloud copy">
    Local and cloud removal are separate actions. Remove the cloud record explicitly if it should no longer be shared.
  </Accordion>
  <Accordion title="A command did not return one JSON document">
    Check `bowerbirds <command> --help` for JSON support. Commands that follow ongoing work may emit newline-delimited JSON events.
  </Accordion>
</AccordionGroup>
