This is the common user-facing path behind screenshots, notes, recordings, and imported files.

<Steps>
  <Step title="Capture or import">
    A person captures through an app surface, a script invokes the CLI, an agent imports a local path, or a website visitor submits through Web Capture.
  </Step>
  <Step title="Preserve the capture">
    Bowerbirds keeps the original material available alongside searchable text and any reviewed annotations.
  </Step>
  <Step title="Choose the location">
    The record lands in private Unsorted, a selected Bucket/directory, a shared Triage shelf, or a Web Capture intake. This step does not require AI.
  </Step>
  <Step title="Process explicitly">
    Optional work may transcribe audio, polish a note, classify a Triage record, analyze a recording, or run a cloud router. Derived output is written separately or as new payloads.
  </Step>
  <Step title="Route and synchronize">
    A person or approved policy files the record to an allowed destination. Only selected shared locations synchronize; local-only and Unsorted records do not.
  </Step>
  <Step title="Consume or compose">
    Apps, the CLI, or agents over MCP search records, fetch selected payloads, add findings, create Packages, or export a portable folder.
  </Step>
</Steps>

## Stable invariants

- Raw evidence remains available when optional processing fails.
- Normal listings, exports, and MCP cannot enumerate Unsorted.
- Payload bytes are fetched deliberately rather than included in every listing.
- Source records are referenced, not rewritten, by Packages.
- Mutable Scratchpads use revisions. Live Dictation normally delivers successful text without filing a record.
- Normal deletion is recoverable.

## A programmatic example

```sh
# Create the destination
bowerbirds bucket create "Checkout investigation" --json

# Import raw evidence without base64
bowerbirds import checkout-investigation /tmp/checkout.png \
  --title "Address validation failure" \
  --tags checkout,regression \
  --json

# Discover the returned record's payloads
bowerbirds item files checkout-investigation <item-id> --json

# Export the whole Bucket for a handoff
bowerbirds bucket fetch checkout-investigation --out ./handoff
```

The equivalent agent workflow over the remote MCP door uses `add_capture` to file, `list_items` and `get_capture` to read, and `sign_items` to mark what it handled.
