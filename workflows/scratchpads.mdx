---
title: "Scratchpads and revisions"
description: "Edit working documents safely without changing immutable source records."
icon: "file-pen"
---

Scratchpads are the mutable document type in Bowerbirds. Every update creates a revision and uses optimistic concurrency so app and agent edits cannot silently overwrite each other.

## From immutable source to working document

To revise a filed Dictation record, create a Scratchpad from it:

```sh
bowerbirds scratchpad from-dictation research <dictation-id> \
  --title "Edited interview notes" \
  --json
```

The original transcript and audio remain unchanged.

Live Dictation normally delivers successful text directly to the active app and creates no record.

## Revision protocol

<Steps>
  <Step title="Read the current document">
    ```sh
    bowerbirds scratchpad show research <scratchpad-id> --json
    ```

    Retain the returned `revision`.
  </Step>
  <Step title="Update with the expected revision">
    ```sh
    bowerbirds scratchpad update research <scratchpad-id> \
      --revision 3 \
      --content "Revised content" \
      --instruction "Clarify the decision" \
      --json
    ```
  </Step>
  <Step title="Refresh on conflict">
    If another writer already created revision 4, your revision-3 write is rejected. Read again, reconcile, then retry with the current revision.
  </Step>
</Steps>

## Agent equivalent

An agent edits a Scratchpad through the CLI, reading the revision first and passing it back:

```sh
bowerbirds scratchpad show research 01J... --json
bowerbirds scratchpad append research 01J... --revision 3 \
  --content "\n\n## Follow-up\nConfirm the launch owner." \
  --instruction "Append the open question"
```

`update` replaces and `append` adds. The `--instruction` becomes part of the revision history.
