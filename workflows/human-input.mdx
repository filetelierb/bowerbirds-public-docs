Agents do not capture anything and do not drive the app. Two explicit mechanisms let a person answer an agent: a structured request for input raised during cloud processing, and a capture the person takes themselves and files where the agent will find it.

<Note>
  The `request_input`, `await_response` and `request_capture_authorization` tools belonged to the retired local MCP server. A remote agent asks for evidence in the record it files, and the person captures it in the app.
</Note>

## Structured request

Cloud processing raises an `rfi` record in a filed Bucket when it needs a decision. Fields can use these kinds:

- `select`
- `text`
- `slider`
- `number`
- `toggle`
- `date`
- `rating`

```json
{
  "slug": "launch",
  "title": "Choose the release channel",
  "message": "The package is ready for one destination.",
  "expiresIn": 3600,
  "fields": [
    {
      "id": "channel",
      "kind": "select",
      "label": "Release channel",
      "options": ["TestFlight", "Production"]
    }
  ]
}
```

The person answers in the app, or from the CLI:

```sh
bowerbirds cloud rfis list --state open
bowerbirds cloud rfis answer <rfi-id> "Use the production workspace"
```

Processing resumes after the answer is filed.

## A capture the agent asked for

An agent that needs to see something files a note saying what and where (`add_capture` with `kind: note`). The person captures it in the Bowerbirds app, annotates it, and files it into the same Bucket; the agent finds it on its next `list_items` with `signed: false` and signs it once handled.

<Warning>
  This is not UI automation. No agent can observe the live Bowerbirds window, capture the screen, click controls, scroll, or enter text.
</Warning>
