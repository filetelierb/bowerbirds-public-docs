A Package is an ordered, portable view over existing context. Use one for a handoff, research bundle, review set, demo, or step-by-step visual guide.

## Golden path for agents

Packages are authored through the CLI; the remote MCP door reads them like any other record.

<Steps>
  <Step title="Find or create a Bucket">
    `bowerbirds buckets --json`; reuse the requested destination or `bowerbirds bucket create` once.
  </Step>
  <Step title="Create or import every source">
    `bowerbirds import <slug> <path>` for screenshots produced by browser automation. For the user's screen, ask the person to capture it in the app.
  </Step>
  <Step title="Resolve payload names">
    `bowerbirds item files <slug> <item-id> --json` for each source. Keep the returned record ID and exact payload name; do not guess `image.png` or `annotated.png`.
  </Step>
  <Step title="Build and validate the Package">
    Compose `package.json`, then `bowerbirds package validate <slug> <item-id> --json` before saving. Resolve missing assets and validation errors first.
  </Step>
  <Step title="Save and verify">
    `bowerbirds package submit <slug> <item-id> package.json`, then `bowerbirds package fetch` and confirm scene, entry, annotation, and resolved-asset counts. `valid: false` means the draft was saved, not completed.
  </Step>
  <Step title="Ask for visual review">
    JSON validation checks graph consistency; it cannot prove a spotlight covers the intended control. Ask the user to open the Package in Bowerbirds.
  </Step>
</Steps>

Cloud Packages are edited in place with `bowerbirds cloud records package-open`, `package-save` and `package-copy`; see the [CLI command reference](/reference/cli-commands).
