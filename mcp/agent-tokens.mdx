An agent acts as its own token, never as a person. A token has one role and one scope, and a workspace owner or administrator can revoke it at any time.

## Roles

| Role | Use when |
| --- | --- |
| `read` | The agent fetches records and signs what it handled |
| `contribute` | The agent also files, moves and trashes records |
| `admin` | The agent also administers Buckets |
| `router` | The agent is a Bucket's [external router](/cloud/external-routers): it fetches, files, derives and signs, and is refused by name at every door that moves, edits, restores or trashes a record |

Use the narrowest role that supports the workflow. `router` is neither wider nor narrower than `contribute`: it adds everything `contribute` adds and can never take anything away, which is what a routing agent left alone needs.

## Scopes

- A **workspace token** opens every Bucket the workspace owns. This is what an approval in the browser grants, and what an agent needs to move a record between Buckets.
- A **Bucket token** opens exactly one Bucket. Mint one by hand when an agent should see nothing else.

## Approved in the browser

When an MCP client, or the CLI's `tokens login`, connects through OAuth, the person signs in, picks the workspace and the role, and approves. The grant is a workspace token held by that client: the client receives an access token that expires after one hour and a refresh token that lasts thirty days and rotates on every use. A refresh token presented twice revokes the whole grant.

## Minted by hand

For an agent with no browser, such as a CI job, mint a token and hand it over. It is shown once; only its hash is kept.

```sh
bowerbirds cloud tokens mint --label "ci reviewer" --role contribute            # workspace token
bowerbirds cloud tokens mint --label "ci reviewer" --role read --bucket me/qa   # Bucket token
```

The Mac app's **Settings → Developer Tools** mints workspace tokens too.

The browser approval and `tokens mint --role` offer `read`, `contribute` and `admin`. A `router` token is minted through the door for now, as an owner or administrator:

```sh
curl -X POST "$BOWERBIRDS_API/orgs/tokens" -H "Authorization: Bearer <your session>" \
  -H "Content-Type: application/json" -d '{"role": "router", "label": "claude code, feedback bucket"}'
```

## See and revoke connections

Every connection of the workspace — approved in the browser or minted by hand — is listed in **Settings → Developer Tools** on the Mac, with its label, role and origin, and a revoke control. From the CLI:

```sh
bowerbirds cloud tokens list [--bucket me/qa]
bowerbirds cloud tokens revoke <id> [--bucket me/qa]
```

Revocation is immediate: the next request refuses, every payload URL the token minted stops working, and its signatures are removed.

## Protect a minted token

- Store it in the client's secret storage or an environment variable.
- Do not commit it to source control.
- Do not paste it into support requests, screenshots, or shared documents.
- Revoke and replace it if it may have been exposed.
