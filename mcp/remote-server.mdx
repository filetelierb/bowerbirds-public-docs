The remote MCP door is an HTTP MCP server with OAuth. A client that supports it discovers the authorization server by itself, registers, and opens an approval page in your browser. You sign in, pick the workspace and the role, and approve. The client receives a short-lived access token and a refresh token; nothing is pasted anywhere.

```text
https://bowerbirds-cloud-y7wboabaoa-uc.a.run.app/mcp
```

<Steps>
  <Step title="Add the endpoint">
    <Tabs>
      <Tab title="Claude Code">
        ```sh
        claude mcp add --transport http bowerbirds \
          https://bowerbirds-cloud-y7wboabaoa-uc.a.run.app/mcp
        ```
      </Tab>
      <Tab title="JSON configuration">
        ```json
        {
          "mcpServers": {
            "bowerbirds": {
              "type": "http",
              "url": "https://bowerbirds-cloud-y7wboabaoa-uc.a.run.app/mcp"
            }
          }
        }
        ```
      </Tab>
    </Tabs>
  </Step>
  <Step title="Approve in the browser">
    The first tool call opens the approval page. Sign in with Google, Apple, or an emailed link. Choose the workspace, the role — `read`, `contribute` or `admin` — and a label, then approve.

    Only an owner or an administrator of a workspace can authorize an agent in it.
  </Step>
  <Step title="Verify the scope">
    Ask the client to list a Bucket's records without making changes. Confirm it sees the intended workspace before enabling a write-capable workflow.
  </Step>
</Steps>

## What the client receives

An access token that expires after one hour and a refresh token that lasts thirty days and rotates on every use. The client refreshes by itself. The approval appears in the workspace's agent connections, under the client's name, where it can be revoked at any time. See [Agent tokens](/mcp/agent-tokens).

## Clients without OAuth

A client that cannot run the browser flow can present a token minted by hand as a bearer header:

```json
{
  "mcpServers": {
    "bowerbirds": {
      "type": "http",
      "url": "https://bowerbirds-cloud-y7wboabaoa-uc.a.run.app/mcp",
      "headers": {
        "Authorization": "Bearer ${BOWERBIRDS_AGENT_TOKEN}"
      }
    }
  }
}
```

Keep the token in the client's secret storage or an environment variable rather than committing it with the configuration.

## Fetching files

Payload bytes never cross MCP. Every payload answers a URL that is short-lived and self-authenticating: the client fetches it with a plain HTTP GET and no credential. See [Tools](/mcp/remote-tools#payloads).

## Plugins

The [Bowerbirds plugins](/integrations/plugins) bundle this endpoint with a skill that teaches the agent how records, payload URLs and signatures work.
